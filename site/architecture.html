Architecture

An ingest job builds a hybrid index in Qdrant. The agent serves search, answers and chat on top of it. Models live on a separate platform tier and are consumed over HTTP.

How a query flows

  1. The agent classifies the query (identifier-like or natural language), which sets the fusion weights.
  2. It embeds the query through the gateway’s embedding leg, then asks Qdrant for dense and BM25 sparse candidates in one batched query, fused with weighted RRF.
  3. Optional steps (cross-encoder rerank, which is off by default; diversification; filters) shape the ranked evidence. /v1/search stops here.
  4. /v1/answer and chat pass the evidence to the reasoning model, then validate citations and compute a verification state before replying.

Sources: architecture guide, retrieval contract, agent contract.

Key decisions

Search never calls an LLM

Only answers, chat and the console use the designated reasoning model. Retrieval is deterministic code, so ranking is testable without a model.

HTTP and model contract

Read-only serving credentials

Serving paths hold read-only Qdrant credentials. Ingest and admin actions use separate writer credentials.

Hard boundaries in AGENTS.md

Stable chunk identity, four chunk types

Chunk ids are deterministic UUID5 keys, derived from the source rather than assigned at random. The chunk-type vocabulary is fixed at four types.

Architecture guide

Abstain on insufficient evidence

Answers carry a verification state. A structured decline is reported as insufficient_evidence, never as an accepted answer.

Verification states in the agent contract

Fixed client error codes

Clients receive fixed messages and stable error codes, never exception or upstream text. Logs carry no secrets or manual text.

Error contract

Pinned air-gap delivery

Images, wheels and BM25 weights are pinned and baked in. There are no runtime downloads, and the bundle is checked offline before it is loaded.

Deployment policy

Models are someone else’s tier

Production reasoning, embedding and rerank models are owned by the platform team behind one gateway. This repository ships no vLLM or gateway on a product path.

Ownership contract

Baseline decisions recorded as an ADR

Qdrant on block storage, FastEmbed BM25, local RRF, and context-in rather than crawl for live state.

ADR-0001

Deployment shape

  • Qdrant runs as a three-replica StatefulSet, unprivileged, on block storage, reachable only inside the cluster. There is no public Qdrant route.
  • The agent runs as a two-replica Deployment. An OAuth-protected console route is optional.
  • Ingest is a one-shot job; the corpus volume may be read-only NFS or a PVC.
  • Jaeger tracing is on by default for this repository’s components.

Source: architecture guide, workloads. Other ADRs: ADR-0003 read-only live state, ADR-0004 operator console, ADR-0005 feedback data boundary.
