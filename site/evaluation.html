Evaluation

Quality claims here are tied to a dated measurement, a commit and a record. Where a measurement has a known weakness, the weakness is stated next to it.

Method

Two rulers

The dev golden set (127 rows) is the set the project tunes against. The frozen holdout (76 rows, sha256-pinned) is meant to catch regressions and is never iterated on. Both are built from a seed set plus payload mining, split deterministically by class. Tests use synthetic documents only. See docs/eval.md, section 7.

Holdout exposure. A contamination audit (#859, record) found that 71 of the 76 holdout rows informed shipped choices. The holdout remains a valid regression gate, because each candidate is compared with its own recorded baseline, but it is no longer an independent quality estimate. No holdout-derived number is shown on this site. All results below are dev-set numbers, and the dev set is the tuning set, so they are not independent estimates either.

Pre-registered adoption rules

A default changes only if a rule written before the measurement is met. For example, the move of the fusion constant rrf_k from 2 to 60 followed a rule registered in #860, checked on the dev set in one session. The retrieval gate requires zero trap failures, no per-class regression beyond a floor, and at least one primary metric improving with a paired-bootstrap 95% interval that excludes zero (2000 seeded resamples).

Paired statistics and live noise

Candidates are compared with paired bootstrap on the same rows. Live runs against real models and a real index carry a few rows of noise, so A/B comparisons run as ABBA replicates (A, B, B, A) to separate the effect from drift. The search-parameter measurement in #842 used that design. Record-replay of captured candidate pools lets ranking changes be swept offline without a GPU.

Answer tier and failure taxonomy

Answer evaluation checks that answers cite, and that abstain rows are not answered. A failure taxonomy (#830, in progress) assigns every failing row one primary class, checking retrieval and packing before blaming model behavior: retrieval_miss, packing_loss, refusal_gold_present, citation_format, content_miss and others. A row with no answer is not_run, never a pass.

Release acceptance

Absolute release criteria on an independent, expert-authored set are specified (section 11, #367) but still proposed, not registered. Until then no run certifies anything.
