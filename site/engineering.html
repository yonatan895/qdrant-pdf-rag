Engineering

How the code is tested, how its supply chain is pinned, and what delivering into an air gap taught the design.

Testing approach

Hermetic by default

Unit tests run without a cluster, a GPU or a network. Air-gap shell tooling is exercised with real Helm rendering and stubbed cluster commands. See docs/testing.md.

Fakes behind the real gateway

Local simulation puts local model servers behind the real, digest-pinned gateway, so the production wire contract (single origin, model-id routing, per-leg keys) is what gets tested. CI rehearses deployment with a documented mock model server.

Property tests

Hypothesis property tests sit in the parser’s own suite, with a bounded dev profile.

Executed browser contracts

The shipped console scripts and templates run in a real headless Chrome against the real routes with a scripted model. Chrome for Testing and its driver are pinned by version and archive digest, and any skipped test fails the job.

Principles recorded in the testing guide: tests lock the claimed path, shared test doubles share builders and pin behavior, and a skipped required check is never counted as a pass.

Supply chain

  • Container images are pinned by digest, Python dependencies by locked, pinned wheels, and the BM25 weights are baked into the image, so nothing is downloaded at runtime.
  • Release bundles carry a checksum manifest with an offline signature. Load re-verifies the signature, then the checksums, then the image digests.
  • A license inventory with bundled notices is generated from the pinned artifacts. It records what can be established and explicitly is not a legal approval (#376, docs/licensing.md).
  • CI actions are pinned by commit SHA, including the one that deploys this site.

Sources: deployment contract, licensing.

Air-gap delivery

Delivery is a five-stage pipeline: pack on a connected host, load into the target environment, deploy, ingest, smoke test, with a pre-flight validation step before any cluster change. The same scripts are rehearsed on a local single-node cluster and in CI without a cluster, so the delivery path is exercised long before it meets a real site.

  • Rehearse what you can, name what you cannot. A local cluster does not implement OpenShift security constraints, so those are first verified on site and documented as such.
  • Prove each model leg before ingesting. A gateway probe checks every leg from inside the cluster and recommends the rerank ordering.
  • Secrets by reference. Per-leg keys live in one operator-created Secret referenced from the manifests, never in the environment file.
  • Fail closed. Storage classes that cannot satisfy the Qdrant contract are refused, and unpinned optional components refuse to render.

Sources: architecture guide, section 3, install and operations guide.
